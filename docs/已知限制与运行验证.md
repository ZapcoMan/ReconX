# 已知限制与运行验证

## 已知限制

- Cookie 分析依赖 `webRequest` 在页面加载时捕获的 `Set-Cookie`：若授权发生在加载之后，需**刷新目标页面**再采集（fetch 兜底读不到 `Set-Cookie`）。
- 受页面 CSP 限制时，`window` 全局变量可能读不到版本，但"是否存在"仍可用；MAIN world 注入（`all-in` / `detector` / `api-extractor` / `routerProbe`）在受限页或 `chrome://` 等页面会失败并降级。
- 指纹命中为启发式线索，存在误报/漏报，须人工确认。
- 前端路由/API 枚举依赖框架内部结构，React Router / Next.js / TanStack 的静态枚举较脆弱，拿不到会回落页面锚点并标注来源。
- **被动采集只读**：`core/router-probe.ts` 仅返回结构数据，不清守卫/不改 meta/不接管 Router。
- **主动探测（梭哈模式）会改写页面**：`all-in.js` / `detector.js` 在页面主世界屏蔽守卫、改写鉴权 meta、拦截跳转——这是**客户端层面**的路由接管，**不绕过服务端鉴权**（受保护接口仍由服务器返回 401/403）；仅在已授权 host、用户显式点击「主动探测」后发生，且 `all-in.js` 会以 `document_start` 常驻注册到已授权 host。接管效果随框架版本与实现差异而不稳定。
- 采集/注入类逻辑（DOM 采集、`detector`/`api-extractor`/`all-in` 读写框架内部、`executeScript`/`webRequest`/`permissions`/`scripting.registerContentScripts`、UI 渲染）依赖真实 Chrome，无法在构建环境实跑，见下方"需 Chrome 实测"。

## 验证方式

ReconX 为**构建型** Vue3 + TypeScript + Vite（@crxjs）扩展，未引入测试框架或第三方运行时依赖（仅 `vue` / `element-plus` / `pinia`）。可复现的自动化校验限于类型检查与构建产物；行为验证需在 Chrome 加载 `dist/` 实测。

### 静态校验与构建（可复现）

- `npm run typecheck` = `vue-tsc --noEmit`：`src/` 全量类型检查（含 `src/core`、`src/extension/content.ts`、`src/background.ts` 与三页 SFC）。
- `npm run build` = `vue-tsc --noEmit && vite build`：产出 `dist/`，含 `manifest.json`、`service-worker-loader.js`、`src/popup|result|options/*.html` 及各自编译后 JS/CSS、content script（`src/extension/content.ts`）、常驻注册的 `all-in.js`、`web_accessible_resources` 中的 `all-in.js`/`detector.js`/`api-extractor.js` 与 result 页脚本、`public/icons` 拷贝。
- `vite.config.ts` 在配置加载前用三次独立 Vite 构建把 `all-in.ts` / `detector.ts` / `api-extractor.ts` 打成 IIFE 输出到 `public/`，构建收尾（`copyToDistPlugin`）再拷入 `dist/`；`stripUseStrictPlugin` 去掉 IIFE 首部 `"use strict"` 以适配页面主世界注入。

> 说明：旧版以 `node --check` 逐 JS 校验、`importScripts` 装载 `lib/*.js`、`content-dom.js` 文件注入的方式已废弃；manifest 由 `vite.config.ts` 的 `defineManifest` 生成。

### 纯逻辑验证（可选，需本地实跑）

`src/core` 下的纯函数库（如 `fingerprints` / `url-classify` / `sensitive-rules` / `header-checks` / `route-urls` / `api-extract` / `tech-stack` / `exporter`）不依赖 `chrome.*`，可用 `tsx`/`esbuild` 或临时脚本单独调用做行为断言；依赖 DOM/`window` 的探测（`router-probe`、`detector`、`all-in`、`api-extractor`）需在页面上下文验证。此类脚本未纳入扩展加载路径，也不随 `npm run build` 执行。

### 需 Chrome 实测（构建环境无法执行）

请在 `chrome://extensions` 加载 `dist/` 后实测：

- 授权/范围：`chrome.permissions.request` 弹窗、`registerContentScripts` 把 `all-in.js` 注册到已授权 host（`document_start` + MAIN world）。
- 被动采集：`executeScript({ func })` DOM 采集、MAIN world `window` 读取与 `routerProbe` 只读枚举。
- 主动探测：敏感路径 GET、路由可达性、`detector.js`/`api-extractor.js` 注入与 `all-in.js` 接管统计（`RECONX_ALL_IN_STATUS` 经 `content.ts` 回传 popup）。
- `chrome.webRequest` 捕获响应头/`Set-Cookie`。
- popup / result / options 的 DOM 渲染、主题切换、原始 JSON 复制与导出下载。
