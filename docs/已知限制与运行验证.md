# 已知限制与运行验证

## 已知限制

- Cookie 分析依赖 `webRequest` 在页面加载时捕获的 `Set-Cookie`：若授权发生在加载之后，需**刷新目标页面**再采集（fetch 兜底读不到 `Set-Cookie`）。
- 受页面 CSP 限制时，`window` 全局变量可能读不到版本，但“是否存在”仍可用。
- 指纹命中为启发式线索，存在误报/漏报，须人工确认。
- 前端路由/API 枚举依赖框架内部结构，React Router / Next.js 的静态枚举较脆弱，拿不到会回落页面锚点并标注来源。
- 不接管前端 Router、不清除路由守卫、不绕过服务端鉴权；前端路由探测仅为 HTTP 可达性核验。
- 采集/注入类逻辑（DOM 采集、`router-probe` 读框架内部、`executeScript`/`webRequest`/`permissions`、UI 渲染）依赖真实 Chrome，无法在构建环境实跑，见下方“需 Chrome 实测”。

## 验证方式

ReconX 是无构建的纯 JavaScript MV3 扩展，未引入测试框架或第三方依赖。

### 静态校验（已执行）

- 所有扩展 JS 通过 `node --check`（Node v24）。
- `manifest.json` 通过 `JSON.parse` 解析。
- `background.js` 的 `importScripts` 所列 11 个库文件均存在。
- `result.html` 引用的脚本（exporter / url-classify / asset-search / dork-library / result / result-extra / result-king）均存在。

### 纯逻辑就地验证（Node 实跑通过）

各逻辑库把对象挂到 `self`（扩展上下文即 `globalThis`）。在 Node 下 `globalThis.self=globalThis` 后 `require` 库、从 `globalThis.X` 取实例即可调用纯函数。示例：

```bash
node -e 'globalThis.self=globalThis;require("./lib/fingerprints.js");const F=globalThis.Fingerprints;console.log(F.identifyFromUrl("https://cdn/x/vue@3.4.21/dist/vue.global.prod.js").name);'
```

### 需 Chrome 实测（构建环境无法执行）

请在 `chrome://extensions` 加载扩展后实测：

- `chrome.scripting.executeScript` 注入、`chrome.webRequest` 捕获响应头/`Set-Cookie`、`chrome.permissions.request` 授权弹窗。
- popup / result / options 的 DOM 渲染与标签互斥（含 `.raw` 隐藏）、原始 JSON 复制按钮。
