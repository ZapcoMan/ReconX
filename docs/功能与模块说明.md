# 功能与模块说明

ReconX 各能力模块、真实运行架构、导出方式与代码结构的详细说明（README 仅保留门面，细节集中于此）。

## 一、功能矩阵

| 模块 | 能力 |
|---|---|
| 技术栈 / WAF / 版本指纹 | 从 Server、X-Powered-By、meta generator、Cookie、资源 URL、`window` 全局、HTML 特征识别框架/CMS/CDN/WAF 与版本线索 |
| Wappalyzer 式技术栈合并 | 交叉 HTTP 头 / cookie / meta / 资源 URL / HTML / window 全局 / 路由结构，输出带**置信度**的技术栈清单，并据此判定站点是否为 Vue/React SPA（合并被动指纹 + 框架检测） |
| 响应头与 Cookie 分析 | 安全头缺失/弱配置、CSP 指令、CORS、`Set-Cookie` 属性（HttpOnly/Secure/SameSite）、缓存与凭据风险 |
| JS 敏感信息扫描 | 外链/内联 JS 中的云密钥、Token、私钥、JWT、内网/元数据地址、source map、Git 痕迹（命中一律原文留存，不做掩码） |
| 链接 / 端点 / 参数收集 | DOM 链接、表单与隐藏字段、iframe、运行时资源、内联 `/api` 端点，按主机/参数归一去重；搜索引擎跳转串与黑名单命中的链接不计入端点，跳过条数与生效规则数在概览如实显示 |
| URL 规范化与敏感分级 | 跳转还原、去跟踪参数、域名/通配/正则黑名单（设置页每行一条，可写 `host`、`*.domain`、`/regex/`）；端点按 critical/warn/info 三级排序 |
| 前端路由枚举与完整 URL | **双源并列**识别 Vue（Vue Router 2/3/4）与 React（React Router / Next.js / TanStack）并枚举全部路由 → 按 Hash/History/base 拼出完整 URL；无法枚举时回落页面锚点。主源 King-CrackX detector，辅源 routerProbe，详见第 2.5 节 |
| API 端点提取 | 实际调用（performance xhr/fetch）+ JS 源码静态正则 + Sourcemap 探测，标注未调用端点（可直接作为 Burp 目标） |
| 前端安全审计 | 敏感 API、未保护路由线索、Sourcemap 泄露 → 风险评级与修复建议，统一并入 bundle 与导出 |
| 资产测绘 / Dork 查询生成 | 生成 Fofa/Quake/Hunter/ZoomEye 与搜索引擎查询语句（**仅生成查询，不自动开标签**）；Dork 分通用 25 条 / 教育 34 条两包，可仅看高风险、可导入自定义条目并持久化、可导出本包备份，另有 5 条不限定当前域的 edu.cn 行业全局查询 |
| 主动探测（默认关闭，受总开关控制） | 须先在设置页打开「启用主动探测」：否则弹窗按钮不可用、background 拒绝 `RUN_PROBES`、常驻接管脚本也不注册。开启后：① 敏感路径 GET 可达性探测；② 判定为 Vue/React 时对枚举路由做 HTTP 可达性核验；③ **梭哈模式**——注入 `all-in` 脚本接管前端路由（详见第四节） |
| 主题切换 | 暗色 / 亮色 / 极客三套；`src/core/themes.ts` 定义令牌，`src/shared/theme.ts` 注入 :root 并联动 Element Plus 明/暗基类与主色；`Settings.theme` 经 background `SET_SETTINGS` 持久化 |
| 范围管控 / 导出 | 允许域白名单 + 逐目标 host 授权；导出集中在结果页：六种格式单发或批量、按风险等级过滤后再导、综合报告 MD（含接管统计/路由完整 URL/审计）、多目标聚合（导入既往 JSON 结果合并成一份 MD） |
| 采集历史 | 每次采集自动留存一份完整结果，最近 20 份；设置页「采集历史」逐份打开、逐份删除、清空全部。索引与全量分键存储，配额吃紧时逐条丢最旧重试，绝不因历史写不下而丢掉本次采集 |

## 二、真实运行架构

ReconX 采用 **background 编排 + content 桥接 + 页面主世界注入脚本** 三层结构，而非单一脚本注入：

### 1. `src/background.ts`（ES module Service Worker，中枢）
- 范围（允许域白名单）读写与逐 host 授权；`chrome.webRequest.onHeadersReceived` 缓存主文档/子帧响应头与 `Set-Cookie`。
- **被动采集**：`chrome.scripting.executeScript({ func })` 直接返回 DOM/资源/表单/内联端点 payload（无独立 DOM content 脚本）；MAIN world 读取 `window` 全局版本；注入 `routerProbe`（只读）枚举框架/路由。
- **JS 分析**：按范围与并发上限 fetch JS，交由 `core/sensitive-rules` 扫描、`core/api-extract` 静态抽端点、探测 sourcemap。
- **主动探测** `runProbes`：入口先过 `inScope` 与 `settings.activeProbe` 双闸门；随后路径探测（`core/probe-routes`）+ 路由可达性（依 `tech-stack` 判定 `enableRouteProbe`）+ 注入 `all-in.js`（MAIN world）并触发 `detector`/`api-extractor`。
- **常驻内容脚本注册**：把 `all-in.js` 以 `document_start` + `world: MAIN` 注册到已授权 host（`chrome.scripting.registerContentScripts`），随范围变更重注册。
- 消息路由：处理页面的 `{action:'reconx*'}` 推送（串行写入**独立键 `liveState`**，与采集结果 `lastBundle` 分离；写入失败补排一次，仍失败则丢弃），以及扩展内 `{type:'...'}` 指令（`GET_STATE/ADD_HOST/REMOVE_HOST/SET_SETTINGS/COLLECT/RUN_PROBES/OPEN_RESULT/FORWARD_TO_CONTENT`）。其中 `ADD_HOST`、`REMOVE_HOST`、`SET_SETTINGS` 三者会重算常驻接管脚本的注册。

### 2. `src/extension/content.ts`（常驻 ISOLATED content script，`<all_urls>`）
- 扩展与页面之间的**消息桥接层**：`window.postMessage` ↔ `chrome.runtime.sendMessage` 双向转发。
- 按需向页面 MAIN world 注入 `detector.js` / `api-extractor.js`（经 `<script src>` 指向 `web_accessible_resources`）；缓存框架检测/路由分析结果供复用；带并发注入锁与错误回传。
- 支持动作：`detectFramework`、`analyzeRouter`、`getAllInStatus`、`extractApi`。

### 3. 三个 MAIN world 独立脚本（由 `vite.config.ts` 预构建到 `public/`，构建时拷入 `dist/`，列入 `web_accessible_resources`）
| 产物 | 源 | 职责 |
|---|---|---|
| `all-in.js` | `src/core/all-in.ts` | **前端路由接管（梭哈模式）**：屏蔽守卫注册、清空存量守卫容器、改写鉴权 meta、拦截 router/history/location 跳转；实时上报拦截统计 |
| `detector.js` | `src/core/detector.ts` | 框架检测 + 路由枚举（Vue/React/Next）；对 Vue 顺带清除守卫、改写鉴权 meta 实现前端路由绕过，React 侧接管由 all-in.js 负责 |
| `api-extractor.js` | `src/core/api-extractor.ts` | API 端点提取：真实请求 + JS 源码静态正则 + Sourcemap 探测 |

### 4. `src/core/*.ts`（被 background 以 ES module 直接 import 的只读规则库/分析器）
`fingerprints` / `sensitive-rules` / `header-checks` / `url-classify` / `api-extract` / `tech-stack` / `collect-extras` / `probe-routes` / `router-probe` / `probe-sources` / `route-urls` / `url-utils` / `security-audit` / `security-report` / `asset-search` / `dork-library` / `exporter` / `themes`。

> `router-probe.ts` 为**纯只读**探测（只返回结构数据，不清守卫、不改 meta、不接管 Router）；`all-in.ts` / `detector.ts` 承载主动探测阶段的接管能力。

### 5. 双源探测与主次判定（`src/core/probe-sources.ts`）

框架与路由存在两条独立采集路径，二者对同一站点**可能给出不一致的结论**，因此不做静默取舍，而是并列呈现交人工判断：

| | 主源 | 辅源 |
|---|---|---|
| 实现 | `detector.js`（King-CrackX 全量分析） | `routerProbe`（ReconX 自研只读探测） |
| 取得方式 | content 桥异步回传，落 `liveState.routerAnalysis` | background `executeScript({func})` 同步返回，落 `bundle.routes` |
| 特点 | 覆盖面更广、与上游结果一致 | 无时序依赖、确定性高 |

判定规则（`buildProbeCompare`）：

- 主源**可用** = `routerDetected` 为真 + 框架可信 + 有路由条目。注意 detector 未识别时 `framework` 仍是默认值 `'vue'`，必须以 `vueDetected`（React 侧为显式 `framework:'react'`）佐证，否则会把"没检出"误读成"是 Vue"。
- 主源可用 → 主源为 `primary`，辅源为 `auxiliary`，**辅源结果照样完整列出**，仅作交叉核对。
- 主源不可用而辅源可用 → 辅源升为 `fallback` 主源，页面顶部明确写出"主源未识别出技术栈，已改用辅源兜底"。
- 两路都不可用 → 提示"两路探测均未识别出可用技术栈"，结果仅作排障参考。
- 两路都可用时输出**分歧清单**：框架、路由库、路由条数（含差值）、基础路径、页面推断路径的逐项差异；路由另给一张并表，标出每条路径被哪一路命中、哪些仅一方可见。

结果页「路由（双源）」分区承载以上全部内容；「技术栈」表因置信度在采集期计算（输入为辅源），另在页面上注明其框架结论以主源为准。

### 6. 结果留存与存储布局（`src/core/bundle-store.ts`）

`chrome.storage.local` 的键与职责：

| 键 | 内容 | 说明 |
|---|---|---|
| `scope` / `settings` | 允许域与参数 | 写走 background `SET_SETTINGS` / `REMOVE_HOST`，保证与常驻注册同步 |
| `lastBundle` | **当前查看的那一份**完整结果 | 采集会覆盖它；从设置页「打开」某条历史也会指向它 |
| `bundleHistory` | 最近结果的轻量索引（id/主机/时间/端点·路由·发现计数/是否探测/是否截断） | 上限 20 条，超出丢最旧；结果页与设置页只读索引，不拖全量 |
| `bundle:<id>` | 每份历史结果的完整数据 | 一条一键，只有打开该条时才读；删除条目时同步移除 |
| `liveState` | 页面脚本实时回传 | 与采集结果分键存储，互不覆盖 |
| `userDorks` | 自定义 Dork（按包分组） | 导入时经 `validateImport` 校验 |

未申请 `unlimitedStorage`，配额约 10MB。因此落盘顺序是：先写 `lastBundle`（失败则写 `shrinkForStorage` 截断副本），再写该条的全量键与索引；写历史失败时**逐条丢弃最旧后重试**，最终仍失败只放弃这一条历史——`lastBundle` 已经落盘，采集不会白做。老用户只有 `lastBundle` 而无索引的，第一次列历史时会自动登记为第 1 条。

管理入口只有一个：设置页「采集历史」分区（逐份打开 / 逐份删除 / 清空全部）。结果页不承担这些动作。

## 三、导出

统一导出在扩展页面内用 `<a download>` 触发（**不依赖 `chrome.downloads`**，规避旧版 MV3 service worker blob 下载失效问题）。实现在 `src/core/exporter.ts`（弹窗/详情页调用）。格式：

- **JSON**：完整结构化结果
- **CSV**：发现项 / 技术栈 / WAF / 端点 / 路由 多维
- **Markdown**：人类可读报告
- **HTML**：自包含样式报告，可直接打开/打印转 PDF
- **SRC 报告**：面向漏洞赏金提交的草稿骨架（等级/位置/证据/复现/影响/建议）
- **端点 TXT**：URL 列表，可直接粘贴 Burp

并支持：**按等级筛选后再导**（对六种格式、批量、综合报告、聚合同样生效）、**综合报告 MD**（含接管统计、路由完整 URL、审计结论）、**多目标聚合导出**（点该菜单项时临时选既往 JSON 结果合并成一份 MD）、**Dork 与链接黑名单的导入导出**。入口都在结果页的导出下拉与设置页，无一项只能靠代码调用。

## 四、梭哈模式（前端路由接管）

- **两条触发路径**：① 「主动探测」时，对判定为 Vue/React 的站点用 `executeScript` 注入 `all-in.js`；② 主机进入允许域、且设置页「启用主动探测」为开时，`all-in.js` 以 `document_start` + `world:MAIN` + `allFrames:true` 常驻注册，此后该站**每次页面加载都自动生效，无需任何点击**。关闭总开关或移除允许域都会撤销该注册。
- **无开关**：脚本内不校验 host、不读设置、不接受外部命令，注入即安装全部拦截；`detector.ts` 的 Vue 路径在分析时同样自动改写，没有任何标志位可以跳过。
- **作用面与深度差异**：Vue（Router 2/3/4）做到三层全接管 + 原型替换 + meta 改写 + 全局 `Array.prototype.push` 钩子；React（React Router data router / TanStack / Next.js）因无集中式守卫与 meta 概念，只做到跳转层。
- **拦截三层**：① 守卫注册层——实例的 `beforeEach/beforeResolve/afterEach` 换成吞掉注册的函数，并 hook `Array.prototype.push`（首参为函数且调用栈含守卫名时静默丢弃）；② 存量守卫层——清空 `beforeGuards/beforeResolveGuards/afterGuards/beforeHooks/resolveHooks/afterHooks` 等容器；③ 跳转层——`router.push/replace/go`、React `navigate`、Next `router.push/replace`、`history.back/forward/go`、`location.assign/replace`、`window.close`。同时把路由 `meta` 中 auth/login/permission 类真值改为 false。
- **接管后仍会枚举**：`scanRouters` 由 DOM BFS + `MutationObserver` + 多个固定延迟重试驱动，持续发现后创建的 Router，observer 不会断开。
- **边界**：全部发生在**客户端（浏览器页面）**，**不绕过服务端鉴权**——受保护接口仍由服务器返回 401/403；能直达前端路由不等于能拿到数据。命中仍为线索，须人工在授权范围内确认。
- 与之相关的撤销缺陷、时序风险与数据留存问题，统一记录在 [已知限制与运行验证](已知限制与运行验证.md)。

## 六、重新生成图标

```bash
npm run gen:icons
```

仅使用 Node 内置模块（`fs`/`path`/`zlib`），无第三方依赖。
